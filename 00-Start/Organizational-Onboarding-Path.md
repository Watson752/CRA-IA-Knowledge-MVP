# Organizational Onboarding Path

Ordered path for a new CRA employee (or vault learner) who needs public structure literacy before reading audits, systems, and data notes.

> Derived onboarding path. Branch mandates and governance facts come from official public sources; the sequence is a vault teaching aid.

## Three buckets (read first)

| Bucket | Role | Index |
|---|---|---|
| Program branches (HQ) | Technical/policy **support** | [[CRA-Program-Branches]] |
| Corporate branches (HQ) | Enterprise **services** | [[CRA-Corporate-Branches]] |
| Regions | Field **delivery** | [[CRA-Regions]] |

No invented reporting lines. Ownership vs assurance: [[Ownership and Assurance Roles]].

### Profile shortcut — Internal Audit + software/data

If you are in Internal Audit with a software/data background, follow [[Learning Path - Internal Audit Software and Data]] (AERB → ITB → SIIB → Security → engagement program branch → DTPB → BI case; cyber/EFMS optional). That path is **derived onboarding**, not an official CRA curriculum.

## Path

```text
CRA
→ Governance
→ Headquarters branches
→ Program branches
→ Corporate branches
→ Regions
→ AERB
→ One audited program branch
→ ITB
→ SIIB
→ A public cross-branch audit case
```

## Step-by-step

### 1. CRA

Read [[Canada Revenue Agency]] and [[CRA-Organizational-Overview]].

**Learn:** What the Agency publicly does (tax, benefits, related programs) and that it has a distinctive Agency governance model.

### 2. Governance

Read [[CRA-Governance-Structure]], then:

- [[Minister of National Revenue]]
- [[Board of Management]]
- [[Commissioner and Chief Executive Officer]]
- [[Deputy Commissioner]]
- [[Taxpayers Ombudsperson]]
- [[Audit Committee]]

**Learn:** Who governs the CRA; which bodies oversee organization/administration versus administration/enforcement of tax law; why incumbents are separated from roles.

### 3. Headquarters branches

Read [[CRA Headquarters Branches]] (legacy summary) and the newer indexes:

- [[CRA-Program-Branches]]
- [[CRA-Corporate-Branches]]

**Learn:** 14 HQ branches + Corporate Secretariat + 4 regions.

### 4. Program branches

Skim all six program branch notes, focusing on mandates:

- [[Appeals Branch]]
- [[Assessment, Benefit, and Service Branch|ABSB]]
- [[Collections and Verification Branch|CVB]]
- [[Compliance Programs Branch|CPB]]
- [[Legislative Policy and Regulatory Affairs Branch|LPRAB]]
- [[Service, Innovation, and Integration Branch|SIIB]]

**Learn:** Who delivers / supports public programs (technical and policy support at HQ).

### 5. Corporate branches

Skim corporate branch notes:

- [[Audit, Evaluation, and Risk Branch|AERB]]
- [[Digital Transformation Program Branch|DTPB]]
- [[Finance and Administration Branch]]
- [[Human Resources Branch|HRB]]
- [[Information Technology Branch|ITB]]
- [[Legal Services Branch]]
- [[Public Affairs Branch]]
- [[Security Branch]]

**Learn:** Who provides corporate support, assurance, technology, security, finance, HR, legal, and communications/privacy services.

### 6. Regions

Read [[CRA-Regions]] and one region note (for example [[Ontario Region]]).

**Learn:** Regions deliver programs via TSOs, tax centres, NVCCs, and contact centres; HQ provides national frameworks and corporate services.

### 7. AERB

Deep-read [[Audit, Evaluation, and Risk Branch|AERB]] and [[Internal Audit and Program Evaluation]].

**Learn:** Who provides independent assurance and publishes the public audit/evaluation reports used in this vault.

### 8. One audited program branch

Pick one MAP-owner example:

- Charities / policy: [[Legislative Policy and Regulatory Affairs Branch|LPRAB]] + [[Internal Audit - Charities Audit Process]]
- Collections: [[Collections and Verification Branch|CVB]] + [[Internal Audit - Accounts Receivable National Inventory]]
- Compliance performance: [[Compliance Programs Branch|CPB]] + [[Evaluation - Audit Yield]]

**Learn:** How a program branch appears as OPI / responsible area / MAP owner.

### 9. ITB

Read [[Information Technology Branch|ITB]] and [[CRA-Technology-and-Risk-Map]].

**Learn:** Who provides technology support and why IT appears even when a program branch owns the business process.

### 10. SIIB

Read [[Service, Innovation, and Integration Branch|SIIB]], [[Chief Data Officer]], and [[CRA-Data-and-Statistics-Map]].

**Learn:** Who provides service, data, and enterprise performance-reporting support.

### 11. A public cross-branch audit case

Read [[Internal Audit - Oversight Use and Continuous Improvement of Business Intelligence]].

**Learn:** Why audits frequently involve multiple branches (SIIB, ITB, CPB, CVB, DTPB, regions) even when one branch leads the MAP.

Optional second cross-branch case: [[Internal Audit - Enterprise Fraud Management System]] (Security Branch + ITB + AERB assurance).

## Quick answers this path should unlock

| Question | Where you find it |
|---|---|
| Who governs the CRA? | Minister, Board, Commissioner, Deputy Commissioner, Ombudsperson |
| Who delivers programs? | Program branches + regions |
| Who provides corporate support? | Corporate branches + Corporate Secretariat |
| Who provides technology and data support? | ITB (technology); SIIB (data/service/performance); DTPB (digital transformation) |
| Who provides independent assurance? | AERB |
| How do regions relate to HQ? | HQ program branches support; regions deliver via field offices |
| Why do audits involve multiple branches? | Processes span owners, IT/data partners, security, and regional delivery |
