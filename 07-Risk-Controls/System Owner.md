**Content class:** general professional concept. CRA public org pages do not standardize “system owner” as a single enterprise title; published audits describe **named maintenance, enhancement, and response roles** instead.

A **system owner** is accountable for a named system’s fitness for purpose— onboarding, rule/configuration governance, performance information, and alignment with policy— distinct from every user of the system and distinct from generic infrastructure operations. Owners may delegate day-to-day work to sections or partners; accountability should still be traceable in audit evidence.

System ownership often **splits** between a business or security custodian and a technical maintainer ([[Control Ownership]], [[IT Controls]]). That split is not an invented org chart; it appears where reports name multiple parties.

**Case-specific illustration (EFMS):** [[Internal Audit - Enterprise Fraud Management System]] states that Security Branch IFMS maintains/enhances EFMS and supports developers, while ITB Enterprise Fraud Management Services also maintains EFMS; Security Branch is MAP owner with ITB jointly named for selected remediation. This vault does **not** infer a single “system owner” title above those report statements or add reporting lines between Security Branch and ITB.
