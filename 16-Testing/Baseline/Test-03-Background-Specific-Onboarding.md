# Test-03: Background-Specific Onboarding (IA + Software/Data)

## Question

Which CRA branches should someone working in Internal Audit with a software and data background learn about first, and why?

## Answer

There is **no official CRA curriculum** in the vault that names this exact employee profile. The sequence below is a **derived onboarding recommendation** composed from:

- [[Organizational-Onboarding-Path]] (branch order AERB → program branch → ITB → SIIB → cross-branch case; Security via optional EFMS case)
- [[Learning Path - New Intern]] (AERB + BI case)
- [[Learning Path - Software Professional]] (cyber, BI, EFMS concept/case path)
- [[Learning Path - Data and Statistics Professional]] (BI, Audit Yield, evidence/data-quality chain)
- [[Learning Path - Auditor]] (case extraction discipline)
- Branch “Why a new employee should understand it,” related domains, and related cases sections

**Official public facts** used below are limited to branch classification/mandates and case-stated roles (OPI, MAP, stakeholders, Three Lines language). **Do not** read this sequence as reporting lines or as AERB “owning” IT, data, or program work.

### Prioritized onboarding sequence (branches)

```text
1. AERB
2. ITB
3. SIIB
4. Security Branch
5. Engagement-relevant program branch (pick one)
6. DTPB
(+ Regions only when the engagement involves field delivery)
```

Then read one primary cross-domain case: [[Internal Audit - Oversight Use and Continuous Improvement of Business Intelligence]], and optionally [[Internal Audit - Specific Cyber Security Controls]] or [[Internal Audit - Enterprise Fraud Management System]] for software/security depth.

### 1. [[Audit, Evaluation, and Risk Branch|AERB]] — learn first

| Field | Content |
|---|---|
| Official public mandate | Independent and objective information, advice, and assurance on the soundness of the CRA management framework and on the effectiveness, efficiency, and economy of strategies, programs, and practices; holistic enterprise risk approach and continuous improvement. Corporate headquarters branch. |
| Why it matters to this profile | This is the public home of Internal Audit / Program Evaluation. Almost every vault case is an AERB product. Clarifies independence, CAE role, Board/Audit Committee context, and MAP follow-up before diving into systems or data. |
| Related knowledge domains | [[Internal Audit and Program Evaluation]], [[Audit Committee]], [[Board of Management]], [[Three Lines Model]], [[Risk Management]], [[Management Action Plan]], [[Public-Audit-Case-Library]] |
| Relevant cases | Publishing branch for all indexed cases; explicitly in cyber (third line) and BI (MAP reasonableness) notes |
| Fact vs recommendation | **Mandate / corporate classification:** official public fact ([[99-Sources/source-notes/SRC-CRA-Org-2025]]). **“Learn AERB first” for an IA employee:** derived onboarding analysis ([[Organizational-Onboarding-Path]] step 7; [[Learning Path - New Intern]]). |

| Fact vs recommendation | **Mandate / IT-to-CBSA note:** official. **BI service delivery / EFMS co-maintenance:** official case-specific facts in those reports. **Prioritize ITB early for software+IA onboarding:** derived analysis ([[Organizational-Onboarding-Path]] step 9; [[Learning Path - Software Professional]] themes). |

### How to act in the first two weeks (derived checklist)

1. Read [[Organizational-Onboarding-Path]] steps 1–7 (CRA → governance → HQ/program/corporate/regions → AERB).
2. Deep-read [[Audit, Evaluation, and Risk Branch|AERB]] + [[Internal Audit and Program Evaluation]] + [[Learning Path - Auditor]] discipline reminder.
3. Read [[Information Technology Branch|ITB]] + [[CRA-Technology-and-Risk-Map]] + start [[Learning Path - Software Professional]].
4. Read [[Service, Innovation, and Integration Branch|SIIB]] + [[Chief Data Officer]] + [[CRA-Data-and-Statistics-Map]] + start [[Learning Path - Data and Statistics Professional]].
5. Read [[Security Branch]] + cyber or EFMS case (respect redactions).
6. Select **one** program branch matching your engagement + its case.
7. Capstone: [[Internal Audit - Oversight Use and Continuous Improvement of Business Intelligence]] (+ optional bridge note [[How the CRA Business Intelligence Audit Supports the Knowledge-Vault Concept]] as **derived analysis**, not an official CRA recommendation).

## Selected branches

1. [[Audit, Evaluation, and Risk Branch|AERB]]
2. [[Information Technology Branch|ITB]]
3. [[Service, Innovation, and Integration Branch|SIIB]]
4. [[Security Branch]]
5. Engagement-relevant program branch: [[Collections and Verification Branch|CVB]] / [[Legislative Policy and Regulatory Affairs Branch|LPRAB]] / [[Compliance Programs Branch|CPB]] (as applicable)
6. [[Digital Transformation Program Branch|DTPB]]

Supporting (not “first,” engagement-dependent): [[CRA-Regions]] when field delivery is in scope.

| [[Assessment, Benefit, and Service Branch\|ABSB]] | Mandate relevant to processing/benefits, but vault onboarding for IA+software/data does not prioritize it; only thin ABS/yield-context links. Include later if engagement is ABSB-scoped. |
| [[Finance and Administration Branch]] | Corporate finance/admin; not featured in software/data learning paths or tech/data cases as a first stop. |
| [[Human Resources Branch\|HRB]] | Workforce stewardship; not a primary IA+software/data entry point in vault paths. |
| [[Legal Services Branch]] | Legal advisory/litigation; not in software/data onboarding sequences. |
| [[Public Affairs Branch]] | Communications/ATIP/privacy leadership; privacy may matter later, but not vault’s first branch set for this profile. |
| [[Domestic Compliance Programs Branch]] | Historical naming; not current structure. |
| All six program branches as a block | Vault recommends **one** engagement-relevant program branch after assurance/tech/data/security literacy. |
| Prompt-only inclusion | No branch was selected merely because it appeared in the user prompt; each selected branch has mandate + onboarding and/or case support in the vault. |
